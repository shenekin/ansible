# Kubernetes Worker Certificates

This directory issues a unique kubelet certificate for each Kubernetes worker and distributes the matching certificates to the corresponding worker. It also issues and distributes a shared kube-proxy client certificate.

The workflow uses the Kubernetes CA generated by:

```text
/root/ansible-playbook/cert/k8s/master/generated
```

## Files

- `inventory.ini`: Worker hosts, addresses, CA source, output paths, and remote certificate paths.
- `issue_node_certificates.yml`: Generates certificates locally and distributes them to each worker.
- `generated/<worker-name>/`: Per-worker private keys, CSRs, certificates, and metadata.

## Prerequisites

- Run `/root/ansible-playbook/cert/k8s/master/issue_control_plane_certificates.yml` first.
- `cfssl` and `cfssljson` must be installed on the Ansible control machine.
- Root SSH access or passwordless sudo to every worker.
- Worker names and `ansible_host` addresses must be correct in `inventory.ini`.
- The Kubernetes CA files must exist under `kubernetes_ca_source`.

## Configure workers

Edit `inventory.ini` and define every worker under `[kube_node]`:

```ini
k8s-node-01 ansible_host=10.168.2.103
```

The playbook creates a unique kubelet identity for each host:

```text
CN=system:node:<worker-name>
O=system:nodes
```

Keep `kubernetes_ca_source` pointed at the generated control-plane CA. Change remote paths only when the node deployment playbook uses different paths.

## Generate and distribute certificates

Run from this directory:

```bash
cd /root/ansible-playbook/cert/k8s/node
source ~/ansible-core/bin/activate

ansible-inventory -i inventory.ini --graph
ansible-playbook --syntax-check -i inventory.ini issue_node_certificates.yml
ansible-playbook -i inventory.ini issue_node_certificates.yml
```

The playbook generates each worker's files locally under `generated/<worker-name>/` and distributes them as:

```text
/etc/kubernetes/pki/ca.crt
/etc/kubernetes/pki/kubelet.crt
/etc/kubernetes/pki/kubelet.key
/etc/kubernetes/pki/kube-proxy.crt
/etc/kubernetes/pki/kube-proxy.key
```

## Verify distribution

```bash
ansible kube_node -i inventory.ini -b -m ansible.builtin.stat \
  -a 'path=/etc/kubernetes/pki/kubelet.crt'
ansible kube_node -i inventory.ini -b -m ansible.builtin.stat \
  -a 'path=/etc/kubernetes/pki/kubelet.key'
ansible kube_node -i inventory.ini -b -m ansible.builtin.command \
  -a 'openssl x509 -in /etc/kubernetes/pki/kubelet.crt -noout -subject'
```

Each worker certificate subject should contain its own worker name. The private keys are installed with mode `0600`.

## Configure kubelet and kube-proxy

The node deployment playbook currently uses bootstrap kubeconfig for kubelet TLS bootstrapping and a separate kube-proxy kubeconfig. The issued files are available for deployments that use static client certificates. If switching kubelet to the issued certificate, configure its service with:

```text
--kubeconfig=/etc/kubernetes/kubelet.conf
```

and create a kubeconfig that references:

```text
certificate-authority=/etc/kubernetes/pki/ca.crt
client-certificate=/etc/kubernetes/pki/kubelet.crt
client-key=/etc/kubernetes/pki/kubelet.key
```

Do not share one kubelet certificate between workers.

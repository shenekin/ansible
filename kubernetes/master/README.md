# Kubernetes 1.25 Binary Control-Plane Deployment

This directory deploys only the Kubernetes 1.25 control-plane components with Ansible. It does not deploy kubelet, kube-proxy, a container runtime, a CNI plugin, or etcd.

The Kubernetes control-plane certificate bundle is expected at:

```text
/root/ansible-playbook/cert/k8s/master/generated
```

The etcd TLS certificate bundle is read from:

```text
/root/ansible-playbook/cert/etcd/generated
```

The inventory group `[kube_control_plane]` defines the target servers.

## Components

The playbook downloads and extracts the Kubernetes 1.25.0 server archive on the Ansible control machine, then distributes these binaries to every control-plane host:

- `kube-apiserver`
- `kube-controller-manager`
- `kube-scheduler`
- `kubectl`

The binaries are installed under `/opt/kubernetes-1.25.0` and linked from `/usr/local/bin`.

## Certificate Functions

The existing generated files are copied to `/etc/kubernetes/pki` with the following names and functions:

| Source file | Installed file | Function |
|---|---|---|
| `ca.pem` | `ca.crt` | Cluster CA used to validate Kubernetes client and server certificates. |
| `ca-key.pem` | `ca.key` | Cluster CA private key used by the controller manager to sign service-account and cluster certificates. Protect this file carefully. |
| `apiserver.pem` | `apiserver.crt` | HTTPS server certificate presented by kube-apiserver. |
| `apiserver-key.pem` | `apiserver.key` | Private key for the kube-apiserver HTTPS certificate. |
| `apiserver-kubelet-client.pem` | `apiserver-kubelet-client.crt` | Client certificate used by kube-apiserver when connecting to kubelets. |
| `apiserver-kubelet-client-key.pem` | `apiserver-kubelet-client.key` | Private key for the API server kubelet client certificate. |
| `front-proxy-ca.pem` | `front-proxy-ca.crt` | Aggregation-layer CA used to validate front-proxy client certificates. |
| `front-proxy-ca-key.pem` | `front-proxy-ca.key` | Aggregation-layer CA private key. It is not required by the running control-plane services but is retained for certificate administration. |
| `front-proxy-client.pem` | `front-proxy-client.crt` | Client certificate used by kube-apiserver for the aggregation layer. |
| `front-proxy-client-key.pem` | `front-proxy-client.key` | Private key for the aggregation-layer client certificate. |
| `sa.key` | `sa.key` | Service-account token signing private key used by kube-apiserver and controller-manager. |
| `sa.pub` | `sa.pub` | Public key used by kube-apiserver to verify service-account tokens. |

The playbook also creates these kubeconfig files:

- `/etc/kubernetes/admin.conf`: administrator access using `admin.pem`.
- `/etc/kubernetes/controller-manager.conf`: controller-manager access using `controller-manager.pem`.
- `/etc/kubernetes/scheduler.conf`: scheduler access using `scheduler.pem`.

The controller-manager and scheduler certificate files remain in the source bundle and are embedded into their kubeconfigs. The playbook does not generate new certificates.

## Prerequisites

- Linux control machine with SSH access to every control-plane host.
- `~/ansible-core` virtual environment.
- Root SSH access, or passwordless sudo on target hosts.
- Debian or Ubuntu targets for automatic installation of `curl`, `tar`, and CA certificates.
- A reachable etcd cluster.
- The Kubernetes API server address and all required API server SANs must match `inventory.ini`.

The inventory is configured for the etcd certificates generated by `cert/etcd/issue_etcd_certificates.yml`. The Kubernetes playbook maps `k8s-master-01`, `k8s-master-02`, and `k8s-master-03` to `etcd01`, `etcd02`, and `etcd03` by their shared IP addresses. It then installs the matching files into `/etc/etcd/pki` on each control-plane host:

```ini
kubernetes_etcd_endpoints=https://10.168.2.100:2379,https://10.168.2.101:2379,https://10.168.2.102:2379
kubernetes_etcd_ca_file=/etc/etcd/pki/ca.pem
kubernetes_etcd_cert_file=/etc/etcd/pki/server.pem
kubernetes_etcd_key_file=/etc/etcd/pki/server-key.pem
```

The source files are `ca.pem`, `<etcd-name>.pem`, and `<etcd-name>-key.pem`. They are installed by this Kubernetes playbook as `ca.pem`, `server.pem`, and `server-key.pem`. The node certificate and key are used as kube-apiserver's mutual-TLS client credentials for etcd.

## Deploy

Run the certificate generation playbook first when the bundle does not exist:

```bash
cd /root/ansible-playbook/cert/k8s/master
source ~/ansible-core/bin/activate
ansible-playbook --syntax-check -i inventory.ini issue_control_plane_certificates.yml
ansible-playbook -i inventory.ini issue_control_plane_certificates.yml
```

Then deploy the control plane:

```bash
cd /root/ansible-playbook/kubernetes/master
source ~/ansible-core/bin/activate
ansible-inventory -i inventory.ini --graph
ansible-playbook --syntax-check -i inventory.ini deploy_control_plane.yml
ansible-playbook -i inventory.ini deploy_control_plane.yml
```

The playbook downloads the archive once to the control machine, extracts it locally, copies the four binaries and certificate files to all control-plane hosts, creates systemd units, enables the services, starts them, and asserts that all three services are active.

## API Server Admission Configuration

The repository contains `admission-config.yaml` in this directory. The control-plane playbook copies it to every control-plane host as:

```text
/etc/kubernetes/admission-config.yaml
```

The `kube-apiserver.service` unit references this file with:

```text
--admission-control-config-file=/etc/kubernetes/admission-config.yaml
```

The configuration uses the `baseline` policy by default and exempts `kube-system`, which is required for privileged Calico system pods. Run the control-plane playbook to distribute the file, update the service units, and restart the API servers:

```bash
cd /root/ansible-playbook/kubernetes/master
source ~/ansible-core/bin/activate
ansible-playbook --syntax-check -i inventory.ini deploy_control_plane.yml
ansible-playbook -i inventory.ini deploy_control_plane.yml
```

Verify the rollout on every control-plane host:

```bash
ansible kube_control_plane -i inventory.ini -b -m ansible.builtin.stat \
	-a 'path=/etc/kubernetes/admission-config.yaml'
ansible kube_control_plane -i inventory.ini -b -m ansible.builtin.command \
	-a "grep admission-control-config-file /etc/systemd/system/kube-apiserver.service"
```

Before deploying Kubernetes, ensure the etcd certificate generation and installation playbook has completed successfully:

```bash
cd /root/ansible-playbook/cert/etcd
source ~/ansible-core/bin/activate
ansible-playbook --syntax-check -i ../../etcd/inventory.ini issue_etcd_certificates.yml
ansible-playbook -i ../../etcd/inventory.ini issue_etcd_certificates.yml
```

## Manual Equivalent Commands

These commands document the important manual operations performed by the playbook. Run them on each control-plane host as `root` only when troubleshooting or performing a manual deployment.

Download and extract Kubernetes 1.25.0:

```bash
cd /tmp
curl -fLO https://dl.k8s.io/release/v1.25.0/bin/linux/amd64/kubernetes-server-linux-amd64.tar.gz
mkdir -p /opt/kubernetes-1.25.0
tar -xzf kubernetes-server-linux-amd64.tar.gz -C /tmp
install -m 0755 /tmp/kubernetes/server/bin/kube-apiserver /opt/kubernetes-1.25.0/kube-apiserver
install -m 0755 /tmp/kubernetes/server/bin/kube-controller-manager /opt/kubernetes-1.25.0/kube-controller-manager
install -m 0755 /tmp/kubernetes/server/bin/kube-scheduler /opt/kubernetes-1.25.0/kube-scheduler
install -m 0755 /tmp/kubernetes/server/bin/kubectl /opt/kubernetes-1.25.0/kubectl
ln -sfn /opt/kubernetes-1.25.0/kube-apiserver /usr/local/bin/kube-apiserver
ln -sfn /opt/kubernetes-1.25.0/kube-controller-manager /usr/local/bin/kube-controller-manager
ln -sfn /opt/kubernetes-1.25.0/kube-scheduler /usr/local/bin/kube-scheduler
ln -sfn /opt/kubernetes-1.25.0/kubectl /usr/local/bin/kubectl
```

Create the required directories and permissions:

```bash
groupadd --system kubernetes || true
useradd --system --gid kubernetes --shell /usr/sbin/nologin --home-dir /var/lib/kubernetes --no-create-home kubernetes || true
install -d -m 0755 /etc/kubernetes /etc/kubernetes/manifests /var/lib/kubelet
install -d -m 0700 /etc/kubernetes/pki /var/lib/kubernetes
chown kubernetes:kubernetes /var/lib/kubernetes
```

Copy the certificate bundle:

```bash
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/ca.pem /etc/kubernetes/pki/ca.crt
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/ca-key.pem /etc/kubernetes/pki/ca.key
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/apiserver.pem /etc/kubernetes/pki/apiserver.crt
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/apiserver-key.pem /etc/kubernetes/pki/apiserver.key
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/apiserver-kubelet-client.pem /etc/kubernetes/pki/apiserver-kubelet-client.crt
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/apiserver-kubelet-client-key.pem /etc/kubernetes/pki/apiserver-kubelet-client.key
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/front-proxy-ca.pem /etc/kubernetes/pki/front-proxy-ca.crt
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/front-proxy-ca-key.pem /etc/kubernetes/pki/front-proxy-ca.key
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/front-proxy-client.pem /etc/kubernetes/pki/front-proxy-client.crt
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/front-proxy-client-key.pem /etc/kubernetes/pki/front-proxy-client.key
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/sa.key /etc/kubernetes/pki/sa.key
install -m 0600 /root/ansible-playbook/cert/k8s/master/generated/sa.pub /etc/kubernetes/pki/sa.pub
```

Install the etcd TLS files generated under `/root/ansible-playbook/cert/etcd/generated`. Use the certificate matching the host's `etcd_certificate_name` from `inventory.ini`:

```bash
install -d -o root -g etcd -m 0750 /etc/etcd/pki
install -o root -g etcd -m 0640 /root/ansible-playbook/cert/etcd/generated/ca.pem /etc/etcd/pki/ca.pem
install -o root -g etcd -m 0640 /root/ansible-playbook/cert/etcd/generated/etcd01.pem /etc/etcd/pki/server.pem
install -o root -g etcd -m 0640 /root/ansible-playbook/cert/etcd/generated/etcd01-key.pem /etc/etcd/pki/server-key.pem
```

Replace `etcd01` with `etcd02` or `etcd03` on the corresponding control-plane host.

Copy the rendered kubeconfig files to `/etc/kubernetes`, place the three service unit files in `/etc/systemd/system`, then start the services:

```bash
systemctl daemon-reload
systemctl enable --now kube-apiserver kube-controller-manager kube-scheduler
systemctl --no-pager --full status kube-apiserver kube-controller-manager kube-scheduler
```

## Validation and Troubleshooting

Run these checks after deployment:

```bash
kubectl --kubeconfig=/etc/kubernetes/admin.conf version --client
kubectl --kubeconfig=/etc/kubernetes/admin.conf get --raw='/readyz?verbose'
ss -lntp | grep -E ':(6443|10257|10259)'
journalctl -u kube-apiserver -u kube-controller-manager -u kube-scheduler -n 100 --no-pager
```

Check TLS etcd connectivity from every API server host:

```bash
curl --cacert /etc/etcd/pki/ca.pem \
	--cert /etc/etcd/pki/server.pem \
	--key /etc/etcd/pki/server-key.pem \
	-sS https://10.168.2.100:2379/health
```

The API server will not become ready until it can connect to etcd and bind its configured address. In an HA deployment, ensure the configured API address resolves or routes correctly from all control-plane hosts and that the API server certificate contains that address as a SAN.
